Minimal Viable 0.1 — System Overview

A bare-bones live camera streaming pipeline: a Python uploader on the device, a Node.js relay server in the middle, and a Next.js page to view the feeds.

1. Relay Server

reccesys001/backend/version01/server.js

Node.js WebSocket relay sitting between cameras and browsers. It accepts two kinds of connections: Pi/camera clients on /ws/pi/<pi_id> and frontend viewers on /ws/feed. Each camera registers itself, then streams binary JPEG frames (with a small JSON header) and periodic health/telemetry reports. The server keeps a map of connected cameras and a set of connected frontends, and simply broadcasts every frame and telemetry update from cameras to all frontends. Also exposes a /health HTTP endpoint listing connected cameras and clients.

2. Collective Feed Page

reccesys001/frontend/version01/src/app/collectivefeed/page.js

Next.js client page that connects to the relay's /ws/feed endpoint and renders a live grid of camera cards. For each camera it shows the latest JPEG frame (base64-decoded), connection status, and a telemetry panel (CPU temp, CPU load, memory, Wi-Fi signal) plus stats like frame number, FPS, resolution, firmware version, frames sent, and data sent. Auto-reconnects every 3 seconds if the WebSocket drops.

3. USB Camera Uploader

reccesys001/scripts/usb_camera_uploader.py

Python script that runs on the camera device. Opens a USB camera via OpenCV (V4L2 backend, falling back to ANY), captures frames asynchronously, encodes them as JPEG via Pillow, and streams them over a persistent WebSocket connection to the relay server. Sends a registration handshake on connect, paces frames to the configured FPS using anchor-based timing, and reports system telemetry (CPU temp, CPU/memory load, Wi-Fi signal strength) every 60 seconds. Reconnects with exponential backoff on network failure, and crashes (for systemd to restart) if the camera hardware appears dead after repeated capture failures.

Data Flow

  • Camera → Relay: usb_camera_uploader.py connects to wss://<relay>/ws/pi/<pi_id>, sends registration, then a stream of frame and health messages.
  • Relay → Browser: server.js rebroadcasts pi_connected, pi_disconnected, frame, and telemetry messages to every connected frontend over /ws/feed.
  • Browser: collectivefeed/page.js consumes those messages and renders a live multi-camera dashboard.

How to Run

1. Relay Server

From reccesys001/backend/version01/:

npm install ws
node server.js

Env vars (optional): PORT (default 8080), PI_PATH_PREFIX (default /ws/pi/), FEED_PATH (default /ws/feed). Health check: http://localhost:8080/health

2. Frontend (Collective Feed)

From reccesys001/frontend/version01/:

npm install
npm run dev

Open http://localhost:3000/collectivefeed. Set NEXT_PUBLIC_WS_URL in .env.local if the relay isn't at ws://localhost:8080/ws/feed.

3. USB Camera Uploader

From reccesys001/scripts/ (on the device with the USB camera, Linux/V4L2):

pip install -r requirements.txt
PI_ID=pi-01 INGEST_URL=ws://localhost:8080 python usb_camera_uploader.py

Key env vars: PI_ID (default pi-default), INGEST_URL (default wss://ingest.example.com/stream — point this at your relay server), USB_CAMERA_INDEX (default 0).

Run Order

  1. Start the relay server.
  2. Start the frontend dev server and open the collective feed page.
  3. Start one or more camera uploaders pointed at the relay — feeds appear live on the page.
